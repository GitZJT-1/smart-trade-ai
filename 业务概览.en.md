## 1. System Positioning

**In one sentence**: An AI sales assistant for foreign trade companies. Covers the full chain from "lead generation to conversion."

```
Lead Generation (Find Customers)     Conversion (Win Orders)
────────────────────────────         ─────────────────────────────
• B2B Platform Diagnosis/Optimization  • Customer Analysis & Outreach
• Social Media Content Strategy        • AI Senior Salesperson
• LinkedIn Marketing                   • Quoting & Negotiation
• Customs Data Mining
```

**Runtime dependencies**:
- `hermes-agent` (AIAgent engine, tool system, cron)
- LLM API Key (user-provided, configured in `~/.hermes/.env`)

## 2. Four Core Business Scenarios

### Scenario 1: Document Q&A (Document Libraries)

Users upload company documents (PDF/Excel/Word/images), and the Agent automatically understands and answers questions about the document content.

```
User: "What is this supplier's MOQ?"
  → Agent reads the document
  → Finds: "MOQ: 500pcs/style"
  → Returns answer + source citation
```

**Supporting modules**:
- `library.py` — manages document libraries (linked to local directory paths)
- `b2b-document` skill — parsing logic for 16 file formats

### Scenario 2: Customer Development (Lead Generation + Conversion)

A user describes a potential customer, and the Agent analyzes and generates a customized outreach email.

```
User: "Help me analyze this customer: https://linkedin.com/in/xxx"
  → Agent extracts company/contact info
  → Determines customer type (price-sensitive/quality-oriented/relationship-based)
  → Generates customized outreach email + follow-up sequence
```

**Supporting modules**:
- `customer.py` — customer CRUD + associated document libraries
- `b2b-lead-generation` skill — Account IQ analysis, cold emails, GAP Selling
- `b2b-linkedin-marketing` skill — LinkedIn content strategy

### Scenario 3: Marketing Content Generation

The Agent, combined with the company's product materials, generates social media content ready for publication.

```
User: "Generate this week's Facebook posting plan"
  → Agent reads company product materials
  → Generates 5 posts (copy + image suggestions + hashtags)
  → User copies and publishes
```

**Supporting modules**: `b2b-social-media` skill (FB/Ins/TikTok/YouTube)

### Scenario 4: Daily Automation

Scheduled tasks execute automatically without human intervention.

```
Every day 09:30  → Agent generates today's LinkedIn Post draft
Every day 17:30  → Agent summarizes today's work → appends to daily report
Every Friday     → Agent generates weekly summary
```

**Supporting modules**: `b2b-daily-automation` skill (7 cron tasks)

```

  │
  ├── trade/bootstrap.py           # Startup: version check, env load, skills sync
  ├── trade/app.py                 # FastAPI app factory + CORS + license check
  │     │
  │     └── trade/api/             # Router submodules split by business domain
  │           ├── companies.py     # Company CRUD
  │           ├── libraries.py     # Document library CRUD + file upload
  │           ├── customers.py     # Customer CRUD + library associations
  │           ├── orders.py        # Order CRUD (3-layer context query)
  │           ├── conversations.py # Conversation history CRUD
  │           ├── onboarding.py    # First-run wizard
  │           ├── chat.py          # /chat + /chat/stream (SSE)
  │           ├── cron.py          # Scheduled tasks
  │           ├── memory.py        # Hindsight long-term memory
  │           ├── license.py       # License validation
  │           ├── deps.py          # Session token validation
  │           └── models.py        # Pydantic request/response models
  │
  ├── trade/helpers.py             # build_query() + create_agent() + provider check

  ├── trade/skill_registry.py      # 17 skills pure data registry
```

## 4. Data Model

```
companies ── 1:N ──► trade_companies  (1:1, is_active and other config)
    │
    └── 1:N ──► libraries      ── N:M ──► customers
                   │                    │
                   └── 1:N ──► conversations
```

**6 data tables**:

| Table | Primary Key | Core Fields | Purpose |
|-------|-------------|-------------|---------|
| `companies` | id | name, slug, contact, is_active | Basic company info |
| `trade_companies` | company_id | data_dir, agent_identity_md, is_active | Trade-specific configuration |
| `libraries` | id | name, root_path, description, company_id | Document library directories |
| `customers` | id | name, contact, note, company_id | Customer records |
| `customer_libraries` | (library_id, customer_id) | — | Many-to-many association table |
| `conversations` | id | query, response, files_read, company_id | Conversation history |

Each table has 3 spare JSON fields (`extra1/2/3`) to avoid future ALTER TABLE operations.

```
│                                              │
│  1. Inject company identity                 │
│     → trade_companies.agent_identity_md     │
│     → or ~/.trade/{slug}/agent-identity.md  │
│                                              │
│  2. Inject document library context (if library_id provided) │
│     → "The user is asking a question within document library X..." │
│                                              │
│  3. Concatenate TRADE_SYSTEM_PROMPT          │
│     → Foreign trade senior sales behavior guidelines │

        │
        ▼
┌─────────────────────────────────────────────┐

│  • Company data directory → ~/.trade/{slug}/│
│  • Agent Loop: Read file → Analyze → Decide → Act │
│  • Tools: read_file, terminal, web_search... │

        ▼

│  → Hindsight.retain() (if configured)      │
└─────────────────────────────────────────────┘
        │
        ▼
  Returns {"response": "...", "conversation": {...}}
```

## 8. Data Isolation Strategy

```
Every request must carry the X-Company-ID Header

X-Company-ID: 1
    → Query companies WHERE id=1
    → Verify is_active=True
    → All DB operations automatically filter by company_id=1
    → Agent data directory → ~/.trade/{slug}/

Switching companies:
    → Frontend dropdown change → update sessionStorage['trade_company_id']
    → All subsequent requests automatically carry the new X-Company-ID
    → Clear current conversation, load new company data
```
