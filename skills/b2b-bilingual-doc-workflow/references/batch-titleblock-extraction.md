# 批量图纸标题栏提取（Масса 单重 / 材质）— 1227544 实战配方

场景：68 个清单项 / 123 个图纸文件（105 扫描 PDF + 12 文字 PDF + 6 图片）一次性提取单重+材质填入清单 xls。2026-08-18 实战验证（1227544 液压缸 111 项）。

## 总流程（7 步）

1. 判文件类型：文字 PDF（`get_text()` 非空）→ PyMuPDF 直读；扫描 PDF → 逐页渲染；图片 → 直接裁
2. 批量渲染所有页的标题栏区域 PNG（横向/纵向分规则）
3. PP-OCRv5 整目录 OCR（`--json` 出全量坐标）
4. 按 `ocr_full.txt` 分隔头切块，坐标顺序对齐到每个文件
5. 坐标法提取 Масса（标签 bbox 正下方数字）
6. 关键词法提取材质（必须滤标题栏标签行噪声）
7. 可疑值裁格放大 2-4x + 像素 ASCII 二次核验

## ① 批量渲染标题栏（PIL/PyMuPDF）

```python
if h > w * 1.3:  # 纵向 A4
    clip = fitz.Rect(w*0.30, h*0.70, w, h)
else:            # 横向（A3/A2 等）
    clip = fitz.Rect(w*0.40, h*0.55, w, h)
pix = page.get_pixmap(matrix=fitz.Matrix(300/72, 300/72), clip=clip)
```
- **多页 PDF 铁律**：`for i in range(len(doc))` 每页都渲染（47 号 26 页、48 号 20 页），标题栏/明细表可能只在某一页
- 图片（tif/jpg）：PIL crop 右下角，宽度 <800px 时放大到 1600px 再存 PNG
- 输出文件名带 tag：`{文件相对路径}__p{NN}.png`，便于回映清单项号（文件名 `{项号}-` 前缀）

## ② OCR 与解析

```bash
ocr_ppocrv5.py <PNG目录> --lang ru --out <out> --json <out>/all_coords.json
```
`ocr_full.txt` 每块头格式：`===== <文件名>（N 行）=====`，与 `all_coords.json` 列表**顺序一一对应**（脚本同一循环 append）——按分隔头切块后顺序切片坐标即可，无需文件名匹配。

## ③ Масса 坐标提取（关键，勿用行序扫描）

```python
MASSA_RE = re.compile(r"^(Масс|Macc|Macco|Mаcc|Мacc|Mass|масс|macc)[аоaы]?$", re.I)
# 值 = 标签 bbox 正下方：
#   y1+3 ≤ by0 ≤ y1+60,  bx0 ≥ x0-90,  bx1 ≤ x1+150,  纯数字
```
- 顺序扫描行会漏值：OCR 里 `Масштаб` 标签常紧跟 `Масса` 标签，行序扫描会被 Масштаб 截断 break
- OCR 变体极多：Macca / Macco / Mocca / Maama / Мeccа / Массо 都要覆盖
- 阈值 60px 内、x 贴近标签列，可避开 Масштаб 列的值

## ④ 材质关键词 + 噪声过滤

```python
MAT_RE = Труба|Круг|Лист|Сталь|Ст3|БрАЖ|БрА9|40Х|30ХГСА|45 ГОСТ|35 ГОСТ|20 ГОСТ|...
NOISE_RE = Изм|докум|Подп|Разраб|Пров|контр|Утв|Копировал|Формат|Инв|Лист
```
坑：
- 标题栏 `Лист/Листов` 标签被关键词 `Лист` 命中 → **必过滤**（实战 36/38 号把 "ЛисТ:" 当材质）
- BOM 行误报（"Кольцо круглое" 等）要人工清
- 装配图（СБ）标题栏**无材质格**（既有 C2.5 铁律）：材质只能从零件图找

## ⑤ 像素 ASCII 核验（OCR 不可信时终审手段）

```python
import numpy as np
from PIL import Image
a = np.array(Image.open(png).convert("L"))
b = (a[y0:y1, x0:x1] < 170).astype(int)
for y in range(0, b.shape[0], 4):
    print("".join("#" if b[y:y+4, x:x+5].max() else "." for x in range(0, b.shape[1], 5)))
```
直接读字形，无需再跑 OCR。实战三种用法：
- **逗号丢失判定**：53 号 300dpi 读出 "3156"，裁格放大后 ASCII 清晰显示 `31,56`（俄式小数点 `,` 被吞 → 100 倍错）
- **Масса vs Масштаб 列归属**：值在各自标签正下方同一列；"12" 若落在 Масштаб 列实为 `1:2`（冒号丢失），不是重量。按 x 列位置归属，勿按 OCR 行序
- **数字宽度判别**：155（三字符宽）vs 1:2（两字符+冒号）肉眼可区分

## ⑥ 该批图纸先验（复用参考）

- КВДЕ/МППА/МЗГ 系列液压缸总装图标题栏大多有 Масса（4,54 / 11.72 / 22.52 / 86,49 …）
- **ПмК 系列（66/67）标题栏 Масса 格空白**；1048-193-00-001~009 全套零件图 Масса 全空白（材质齐全）——系列图纸 Масса 留空是常态，标 `[待核]` 或找图纸内尺寸表，勿硬编
- 同图号多张图值不同（33 号：3893 主图 3102,22 vs 3893-01 变体 459,6）→ 以清单名称所指图号为准
- 单重合理性自检：40mm 缸径液压缸不可能 3 吨；单重对零件尺寸明显过大 = 逗号丢失，必复核

## ⑦ 断点续跑 + 二次核验（2026-08-18 第二轮实战补充）

**断点续跑（上一轮被工具调用上限打断时）**：
- 先 xlrd dump 目标 xls 现状（Sheet2 C/D 列），看哪些行已被写入。上一轮只写了 1-5 号单重（4,54/5,32/30.23/86,49/23,36），与重跑 OCR 结果完全一致 → 复用不覆盖
- 上一轮可能残留错误单元格：91 号 材质 列被写成清单品名文本 → 按新提取结果覆盖
- OCR 中间产物不落盘则全部重来：渲染 → OCR → 解析一条龙写成脚本，中间结果存 JSON，避免再次中断丢进度

**解析 all_coords.json 两个必踩坑**：
- 每行是 dict `{"text","score","bbox"}` 不是 tuple——直接 `for t, sc, bb in lines` 解包拿到的是键名字符串（全 None），必须 `c.get("text")` 取字段
- score 可能是 str，比较前判 `isinstance(sc,(int,float))`

**bbox 坐标系必须与图配套**：坐标来自 full 整页渲染（200dpi）时，裁单元格图必须用同一 full 目录的图；用 tb 目录（300dpi 裁剪图，尺寸不同）会裁出 BAD BOX / 空白区

**Масса 值位置不只在标签正下方**：纵向标题栏（15 号）数值在标签同行左侧（51.90 在 Macca 左边）——坐标法（只找下方 3-60px）找不到时，扫同行左右 ±200px

**空白 vs 漏检必须复核**：坐标法返回 None 后裁单元格放大 OCR/ASCII 终审——66/67（ПмК）、1048-193 零件图、34/37/39/107/108 都是真空白（系列图纸常态，标 `[待核]`），不是解析失败；34 号 OCR 出的 "13" 是左侧注释序号不是单重（按 x 列归属判断）

**跨文件同图号复用**：89 号（1029-06-06-200СБ корпус）的 Масса 8,7 出现在 47 号多页 PDF 第 24 页——多页装配 PDF 常含其他清单项的零件图，先扫多页文件再单独找单页

**多页装配 PDF 内部结构**：p1 总装页（标题栏有整机 Масса，如 47 号 = 28,3）+ БОМ/спецификация 页 + 每零件一页（零件标题栏有零件单重 + 材质，如 48 号 ШТОК: Масса 1,9 + "45 ГОСТ 1050-88"）

**标题栏 Масса 空白时查图纸内尺寸表**：102 号标题栏空白但图内尺寸表有 "Macca, kг" 列 = 62,36；13 号标题栏写 "см. таблицу"（见图内表）——系列图纸单重从尺寸表按规格行取值，勿硬编
