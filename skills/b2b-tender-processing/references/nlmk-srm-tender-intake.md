# NLMK SAP SRM 招标邮件入库流程

## 来源

NLMK（新利佩茨克钢铁）招标通知通过 SAP SRM 系统发出，经 `colleague@example.com` 转发到 `user@example.com`。

邮件特征：
- 主题：`Fw:Конкурс  {номер}/0`（如 `20155619/0`）
- 正文为 base64 编码俄语转发内容，含 SRM 门户直链
- 必含附件 `0.PDF` — SAP SRM 导出的完整招标书
- 可选附件：图纸（.pdf/.7z/.jpg）、产品照片（.png/.jpg）、规格链接（.docx）

## 0.PDF 结构

PDF 为 SAP SRM 自动生成的俄语招标书，包含：

### 元数据区（通常在 P1 顶部）
- **Описание** — 招标标题（如 `Поставка Главный вал 1068868619 СГОК`）
- **Номер конкурса** — 招标编号（`20155619/0`）
- **Валюта конкурса** — 主币种（通常 RUB）+ 允许的附加币种
- **Процедура конкурса** — Закрытая процедура（关闭式）
- **Пеериод подачи** — 报价提交窗口 → 截止日期
- **Примечание закупщика** — 采购方备注（交付条件、付款条件、评标标准）

### 明细表
```
Поз. | Тип позиции | Дата поставки | № продукта | Название | Количество
```

### ⚠️ 版本陷阱
- **必须读取 PDF 所有页**。0.PDF 可能有多页（通常 1-2 页），第 1 页可能是旧版本，后续页为 `Версия: 1`（更新版）
- 旧版本中被删除的项标注 `Эта позиция удалена!`
- **以最高版本号所在页为准**（通常最后一页），旧版已删项单独记录

### ⚠️ 分页截断
部分 PDF 的行项会被页面边界截断（如 `№ продукта` 在 P1 末、`Название` 在 P2 首）。核对时需跨页拼接，不能仅凭单页判"缺字段"

## 入库步骤

### 1. 定位邮件
邮件监控脚本将投标邮件存入：
```
C:/Users/<user>\Desktop\邮件结果\{YYYYMMDD}_user@example.com\招标_{номер}\
```

### 2. 提取 PDF 内容
用 `pymupdf`（`import fitz`）逐页读取 `0.PDF`：
```python
doc = fitz.open(pdf_path)
for page in doc:
    text = page.get_text()
```

### 3. 解析关键字段
- 从 `Информация` 区块提取：招标编号、采购方、币种、截止日期、交付/付款条件
- 从 `Конкурс подробно` 表格提取：Поз. / № продукта / Название / Количество
- 标注「已删除」项（`Эта позиция удалена!`）

### 4. 创建项目文件夹
路径规范：
```
C:/Users/<user>\Desktop\沈阳山泰通用机械有限公司\报价单\{номер}_{краткое_описание}\
```
краткое_описание 取自 0.PDF 中 `Описание` 字段的**完整内容**（含交付地点如 СГОК/НЛМК/Липецк），空格替换为下划线。

如：`20155619_Главный вал 1068868619 СГОК`（✅ 含 СГОК）
**非** `20155619_Главный вал 1068868619`（❌ 缺少交付地点）

**参考模板**：`C:/Users/<user>\Desktop\260714-20154515舱口盖-已报价` — 该目录展示了最终交付物标准结构（`0.PDF` + `1 xxx` + `2 xxx` + `询价单.xlsx`）。

### 5. 排序编号附件

从 `招标_{номер}\attachments\` 复制附件到项目文件夹，**排序并重命名为 `{序号} {描述}.{扩展名}`**：

**规则**：
- **排除**：0.PDF 保留原名不动（`0.PDF`）；.eml 邮件文件**不入库**（仅用于提取附件，不复制到项目文件夹）
- **排序**：按原始文件名字母序排列
- **命名**：`{序号} {简短描述}.{扩展名}`
  - 序号从 1 开始递增
  - 描述从附件名提取产品标识部分（去除前缀时间戳 `17407240XX_`、后缀时间戳 `_2026...`、`_X` 标记）
  - 保留关键产品号/图号如 `ОЗМ 1189`、`7DC CB 2211`
- **示例**：`1 Главный вал 1068868619 ОЗМ.pdf`、`2 Втулка конуса МР1250 ОЗМ 1189.pdf`、`3 Пружина 2GS-2452.01.02-04.pdf`

**铁律**：附件必须排序编号。最终文件夹结构应与模板 `260714-20154515舱口盖-已报价` 一致：

```
报价单\{номер}_{описание}\
├── 0.PDF                          ← SAP SRM 招标书（原名不动）
├── 1 {описание附件1}.{ext}        ← 附件 1（排序编号+描述名）
├── 2 {описание附件2}.{ext}        ← 附件 2
├── 3 {описание附件3}.{ext}        ← 附件 N
└── {номер} {описание} 询价单.xlsx  ← 询价单（由步骤 6 生成）
```

### 6. 生成询价单 Excel

文件名：`{номер} {краткое_описание} 询价单.xlsx`（如 `20155619 Главный вал 1068868619 询价单.xlsx`）

**模板结构**（参考 `260714-20154515舱口盖-已报价\20154515舱口盖等询价单.xlsx`）：

**实测结构（openpyxl 解析）：**
- Sheet 名: Sheet1
- Row 1: 表头行（单行，`\n` 在单元格内换行）
  - 序号 | 物料号 | 名称 | 中文名称 | 数量\npcs | 图纸单重\nkg | 总重 | 材质 | 单价 | 总价 | 交货期\nLead time
- Row 2+: 数据行（从第 2 行开始，不是第 12 行！）
- 末行: Итого / Total（A:C 合并，SUM 公式在数量列）
- **无 Номер конкурса / Закупщик / 条件摘要 等信息行** — 模板是纯询价表格

**关键格式细节：**
- 表头字体 Arial 11, 数据字体 Times New Roman 11（俄文）/ 宋体 11（中文）
- 全部单元格 thin 边框、居中、自动换行
- 表头行高 30, 数据行高 14.4
- расчетные 列（图纸单重/总重/材质/单价/总价/交货期）留空供工程师填
- 列宽: A=9.0, B=14.25, C=34.5, D=27.63, E=9.0, F=13.0, G=11.75, H=17.5, I=11.63, J=11.63, K=11.75

**必须填入的字段**：
- 序号、物料号 (№ продукта)、名称 (Название)、中文名称、数量
- 招标元信息（编号、采购方、截止日期、币种、条件）

**留空待填的 расчетные 字段**：图纸单重、总重、材质、单价、总价、交货期 — 这些需要工程师根据图纸计算后填入

**注意**：
- 已删除项（`Эта позиция удалена!`）不计入有效项，可在 Примечание 列标注
- 标准样式：Arial 字体、thin 边框、居中/左对齐混排

### 7. 一致性核对
核对原则：**询价单明细（PDF 行项）与附件（图纸/规格）一一对应，无遗漏**。
- 行项数量 vs 附件数量（不含 0.PDF 和 EML）
- 产品代码 vs 附件文件名中的关键词
- 版本间是否有增减项

## ⚠️ 工作流区分 — 别串流程

本流程（SRM 邮件入库）与「报价单整体招标整理」是**两个不同的工作流**，不可混淆：

| | SRM 邮件入库（本流程） | 报价单整体招标整理 |
|:--|:----------------------|:-------------------|
| **触发** | 用户说「新标需要整理」「邮件里的招标入库」 | 用户说「整理报价单中的招标」 |
| **输入** | `邮件结果\{date}_<account>\招标_{номер}\`下的 EML + 附件 | 报价单目录下已存在的项目文件夹 |
| **输出** | 每个标一个独立文件夹 `报价单\\{номер}_{описание}\\`（含 `0.PDF` + `N 附件` + `询价单.xlsx`） | 一份汇总报告 `报价单\\NLMK招标整理_一致性核对报告_YYYYMMDD.xlsx` |
| **铁律** | 逐标入库，每个标单独建文件夹 | 不要为每个标单独建文件夹，那是入库流程的事 |

**当用户问「处理结果在哪」时，必须回答本流程对应目录下的实际文件。不要把 NLMK 汇总报告的路径当成本流程的交付物。**

## 常见陷阱

| 陷阱 | 现象 | 处理 |
|:-----|:-----|:-----|
| PDF 多版本 | P1 含已删项，P2 为最新版 | 读全部页，以最高 Версия 为准 |
| 行跨页截断 | 产品代码在 P1 末、名称在 P2 首 | 跨页拼接，勿判为缺字段 |
| 已删项误入清单 | `Эта позиция удалена!` | 标灰斜体单独列出，不计入有效项数 |
| 附件名含特殊字符 | 括号、空格导致路径问题 | 使用原始文件名，不重命名 |
| **串流程** | 用户问 SRM 入库结果，回答却指向 NLMK 汇总报告 | 交付物必须与流程对应：入库→项目文件夹+询价单.xlsx |
| **附件未排序编号** | 附件用原始长文件名（`17407240XX_..._X.pdf`）散放，无序号 | 必须重命名为 `N {描述}.{ext}` 格式（如 `1 Главный вал ОЗМ.pdf`），参照模板 `260714-20154515舱口盖-已报价` |
| **询价单格式错误** | 生成 `清单 {номер}.xlsx` 只有简要列（№/物料号/名称/数量） | 必须用标准询价单模板：`{номер}{描述}询价单.xlsx`，含完整 расчетные 列（单重/总重/材质/单价/总价/交货期）+ 招标信息抬头 |
| **文件夹名缺交付地点** | 如 `20155619_Главный вал 1068868619` 缺少 СГОК | 文件夹名用 PDF 中 `Описание` 的全文，含交付地点（СГОК/НЛМК/Липецк 等），下划线替代空格 |
