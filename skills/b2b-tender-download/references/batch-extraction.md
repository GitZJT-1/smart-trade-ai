# 批量解压实战记录（2026-08-05，КФ_解压 / БФ_解压，669 包）

## 场景
报价单目录下两个解压中转文件夹（`КФ_解压`、`БФ_解压`，各含 bf_*/kf_* 子目录），存放从
招标站下载的 7z/zip/rar 图纸包。用户要求"所有未解压的文件夹解压到原文件对应地址"。
实际含义 = 每个压缩包解压到**其所在目录下的同名文件夹**（与目录中已存在的
`Колесо червячное К1887\`、`Узел крепления траверсы ...\` 等既有解压结构一致）。

## 规模与结果
- 首轮扫描 669 个压缩包（.7z 559 / .zip 101 / .rar 11，共 2.48 GB，磁盘余 52 GB）
- 首轮：成功 578、已存在跳过 50、失败 41（全部 7z 错误码 2），115 秒
- 二次补处理（重新 os.walk 发现的新包 + 特例）：6 个中 5 个成功
- 终检：现存 118 压缩包、未解压 0；解压出约 30,500 文件 / 10.5 GB

## 关键经验

### 1. 7z 退出码映射
| 码 | 含义 | 处置 |
|----|------|------|
| 0 | 成功 | — |
| 1 | 警告（非致命） | 检查目标目录 |
| 2 | 致命：损坏/格式不支持 | 记 FAIL；内容可能已平铺在同目录（源包损坏但图纸散落） |
| 3 | 不可恢复 | 记 FAIL |
| 4 | 需要密码 | 记 FAIL，问用户要密码 |

### 2. 乱码文件名（mojibake）是最大坑
- 现象：`УРАЛКРАН\搻€媻悁_€_悡憖_佮犫岐.zip` 这类文件名——俄文 UTF-8 被按 GBK 误读
  再转码，含 PUA 字符（如 `\ue127`）。
- **手打/从日志复制路径必失败**（Python 报 `[Errno 2] No such file or directory`，
  7z 报"系统找不到指定的文件"）。原因：日志/终端显示的字符序列 ≠ 磁盘真实文件名。
- 正确姿势：`os.listdir(dir)` 取回**原样文件名**（注意 `repr()` 会显示 `\ue127` 之类
  转义），用该字符串拼路径，`os.path.exists` 验证后再操作。
- 7z 对这类路径常失败，但 Python `zipfile` 解压内容完好（zip 内条目名也是乱码，
  PDF 等文件内容不受影响）。

### 3. 点结尾的目录名/压缩包名
- 案例：`Желоб квадратный Noell с изм. 2019г..zip` → 目标 `...2019г.`（尾点）。
- Windows 目录名不能以点结尾：7z 建了空目录（rc=0 但目标 0 项），`-o` 参数尾点被吞。
- 解法：目标名 `rstrip(".")`，并用 Python `zipfile` 解压（pyzip 对目标目录名无此限制）。
- 已并入 `scripts/batch_extract.py` 的 `extract()`：目标尾点自动去点 + zip 兜底。

### 4. 嵌套压缩包必须重扫
- 一个 7z 解压后内部常再嵌套 7z/zip/rar（如 `Механизм маркировки ...\Узел подшипниковый
  ...СБ.7z` 藏在外层解压结果里）。
- 首轮 os.walk 收集的清单不含"解压产物里的新包"→ 解压一轮后**重新 os.walk** 补处理，
  循环直到 0 个未解压。本会话正是这样补出 6 个新包（含嵌套 rar 副本、`_zip` 后缀的
  真 zip——文件头 `PK\x03\x04` 判断，不能只看扩展名）。

### 5. 外部流程边解压边移走源文件（本用户环境常态）
- 现象：首轮 [OK] 578 个，结束后抽查 200 个源包只剩 42 个存在；41 个 FAIL 源包全部消失。
- 原因：用户环境有其他会话/微信/归档脚本在移动文件（与陷阱 14、15 同源）。
- **源包消失 ≠ 解压失败**。终态判据 = 对**现存**压缩包逐一检查同名目标目录非空，
  全部满足即完成。汇报时给"成功 N / 跳过 M / 失败 K + 终检未解压 0"格式，别报
  "源文件被移走"当失败。

### 6. 其他
- 日志用 `utf-8-sig`（中文 Windows 记事本/GBK 环境可读）。
- 同名目标已存在且非空 → SKIP（断点续解，避免重复解压覆盖）。
- 统计文件数/大小时 `os.path.getsize` 可能 FileNotFoundError（外部流程正在移文件）——
  用 try/except 容错，别让统计脚本崩。
- 首次全量扫描与脚本扫描数字可能差 2 个（外部移动的时序竞争），以脚本自身收集为准。
