# 双语外贸文档处理工作流（俄/英）

## 场景概述

俄罗斯/乌克兰客户（钢铁、冶金、机械行业常见）发来的合同/规格书/图纸/拍品清单，俄英双语混排。三种结果需求：

- **工作流 A**：客户合同/规格书 PDF → **发货文件**（发票 docx + 箱单 docx + 报关单 xls）— 信息与合同一致、格式与模板完全对应
- **工作流 B**：客户拍品清单 XLS + 图纸 ZIP → **询价表 XLS**（供与工厂技术对接报价）
- **工作流 C**：客户工程图纸（TIFF/PDF 扫描件）→ **OCR → 翻译 → 询价表 / 注释对照表 / 带注释图**

## 铁律

1. **信息以源文件为准，禁止编造** — 价格/数量/日期/合同号/规格书号逐字核对，不确定就标 `[待补充]` 问用户
2. **格式以模板为准** — 表头、列序、俄英双语结构必须与用户提供的模板完全一致，禁止自创列结构
3. **俄语/乌克兰语品名保留原文**，附加贴合行业的中文翻译，格式如 `Втулка ч.4-435281 | 衬套 件号 4-435281`
4. **单价/总价在报价前留空**，不得猜测

## 文件识别

| 输入 | 特征 | 处理 |
|---|---|---|
| 文字型 PDF | `get_text()` 非空 | 直接提取 |
| 扫描型 PDF | `get_text()` 为空（0 chars） | 渲染 300dpi PNG → OCR（rus+eng） |
| 俄语 XLS | Наименование, Кол-во, Поставщик | xlrd 直读 |
| 乌克兰语 XLS | Найменування, Кіл-ть, Одержувач（含 і/ї/є 字符） | xlrd 直读，按俄语词根翻译 |
| 图纸 ZIP | 每个零件一个子目录 `N-名称 ч.件号` | 解压后与清单 Lot 一一映射 |

## 工作流 A：合同/规格书 → 发货文件（发票 + 箱单 + 报关单）

### A1 读取合同（多页处理 + OCR + 字段提取 一条命令）

```bash
PY="$SKILL_DIR/.venv-skill/Scripts/python.exe"
"$PY" "$SKILL_DIR/scripts/ocr_pdf.py" "<合同.pdf>" --out "<输出目录>"
```

脚本自动完成：
- **遍历所有页**：每页 `get_text()` 判文字/扫描，混合文档分别处理
- 扫描页 300dpi 渲染 PNG → Tesseract OCR（rus+eng，`--tessdata-dir` 防中文路径乱码）
- 字段提取：宽松锚点 + 特征数字兜底（合同号 16-20 位、规格书号 10 位、金额俄式小数点归一化）
- 输出 4 个文件：`ocr_full.txt` 逐页全文 / `pages/page_NN.png` 渲染图 / `fields.json` 字段+来源页 / `verify_list.txt` 待核清单

字段表（自动提取）：规格书号 Спецификация / 合同号 К договору № / 招标号 Tender / 总金额 Итого сумма без НДС / 币种 Валюта / 交货条款 Условия поставки (DAP) / 付款条款 Условия платежа / 交货期 Срок поставки / 合同日期 от / 供应商 Поставщик / 买家 Покупатель / 制造商 Завод изготовитель

### A1.5 字段交叉校验（vision 双路径，按可用性降级）

ocr_pdf.py 已把低置信度/长数字字段写入 verify_list.txt。核对方式按可用性降级：

- **路径 1（推荐，工具可用时）**：用 Hermes `vision_analyze` 加载 `pages/page_NN.png`，逐项核对 verify_list 中的字段（长数字 OCR 常把 1→7、0→8 认错，vision 直接读像素最可靠）
- **路径 2（vision 不可用时自动降级）**：只核对 verify_list.txt 列出的条目（通常 8-12 条），不是全文
- 修正字段后更新 fields.json（直接编辑该文件即可）

### A2 字段规则（供人工校对/复提取参考）

| 合同字段 | 俄语原文示例 | 去向 |
|---|---|---|
| 规格书号 | Спецификация **4600114993** | 箱单 Specification No.、报关单规格书编号 |
| 合同号 | К договору № **100000000000380622**（样例 18 位，勿假设固定位数） | 箱单 Contract No.、报关单合同协议号 |
| 供应商 | Поставщик / Supplier + 地址 | 发票 Suppler、箱单抬头 |
| 买家 | Покупатель / Buyer + 地址（俄+英双语） | 发票 Buyer、箱单 TO MESSRS |
| 商品行 | № \| Code \| Наименование \| Q-ty \| UoM \| Price \| Валюта \| Amount | 发票/箱单/报关单商品行 |
| 交货条款 | Условия поставки: **DAP г. Липецк** | 发票 Terms of delivery、报关单成交方式 |
| 付款条款 | Условия платежа: 100% в течение 15 дней | 发票 Terms of Payment |
| 交货期 | Срок поставки: 31.07.2026 | 发票/箱单日期参考 |
| 总金额 | Итого сумма без НДС: 53 000,00 | 发票 TOTAL / ВСЕГО |
| 制造商 | Завод изготовитель: ... | 报关单申报要素参考 |

### A3 定位模板 + 结构 dump

- 用户提供「发货文件」目录，内含 `*发票.docx`、`*箱单.docx`、`*报关单.xls`
- **模板只提供格式骨架，主体信息一律取自合同** — 模板里可能是别的公司名，必须替换成合同中的实际供应商/买家
- **新模板首次使用跑一次 dump**（产出结构档案，替代人工记录）：

```bash
"$PY" "$SKILL_DIR/scripts/dump_template.py" "<新模板.xls>" --cells --out struct.md
"$PY" "$SKILL_DIR/scripts/dump_template.py" "<新模板.docx>" --out struct.md
```

### A3.5 生成策略判断（先判同订单，再选策略）

- **同订单**（模板规格书号/合同号与合同一致）：直接复制模板 + 程序化字段校验（A7）即可 — 生成结果与模板一致是**预期行为**，勿为"显得在生成"而从零构建合并单元格 docx（易错、格式退化）
- **异订单/新合同**：套模板骨架，逐字段替换为合同提取的数据
- 合同未载明字段（毛净重/体积/HS 编码/信用代码/申报要素）→ 沿用模板同订单已验证数据，交付报告**注明来源**（来自合同 vs 沿用模板）

### A4 生成发票（docx）

python-docx 复刻模板表格（典型 9 行 × 5 列，俄英双语）：

- 供应商/买家：俄语名 + 英语名 + 地址（双语分行）
- Terms of delivery / Условия поставки：DAP ...
- Country of origin: China / Страна происхождения: Китай
- Terms of Payment / Условия оплаты
- 表头：`Marks & numbers//Наименование и номера | Number & kind of packages, description of goods//Количество и вид упаковок, описание товара | Quantity//Количество | Unit price//Цена | Amount//Сумма`
- 商品行：`编号/俄语品名/规格` | 数量 | 单价 | 金额
- 结尾：`TOTAL /ВСЕГО: ¥金额` + 供应商名称 + 日期

**发票商品行对齐构造**（用户定稿版规则，以此为准）：模板 R7 只有 2 个 tc —— C0 空 + C1 跨 4 列大单元格（gridSpan），商品行/Total/落款/日期全在 C1 内按段落排布。用户定稿偏好：**品名与数字合并到同一段**：

```text
p1:  代码（单行）
p2:  品名 0-28
     + 空格填充到 45（数量列起点：填充量 = 45 - len(品名)）
     + 数量左对齐 @45
     + 10 空格（46-55）
     + ￥ @56 + 单价 10 宽左对齐 @57-66
     + ￥ @67 + 金额左对齐 @68+
p7+: TOTAL /ВСЕГО: ￥金额 + 供应商名 + 日期
```

**通用公式**（品名长度 L ≤ 45 时）：`品名 + ' '*(45-L) + str(qty) + ' '*10 + '￥' + str(price).ljust(10) + '￥' + str(amount)`。数量列固定 45、￥固定 56/67。

**构造方式**：p2 保留 run 结构按边界分配；全表替换用段落级（合并 runs 后 replace 完整词再写回）——w:t 级替换对跨 run 文本（日期分片）无效。

### A5 生成箱单（docx）

- 抬头：供应商公司名 + 地址；标题 `Packing List` / `Упаковочный лист`
- `TO MESSRS/К ГОСПОДАМ:` 买家名 + 地址（俄+英）
- `Contract/Договор No. [合同号]  Date/Дата: [日期]`
- `Specification/Спецификация No. [规格书号]` ← 来自合同 A2
- `Terms of delivery: DAP ...` + `Country of origin: China`（双语行）
- 表格 7 列：`Description of goods//Описание товаров | Qty//Кол-во | Unit//Единица измерения | Package//Упаковка | N.W.(kg)//Вес нетто | G.W.(kg)//Вес брутто | Volume/m3//Объём/м3`
- `Total//Всего` 行：数量/件数/毛净重/体积合计
- 结尾：供应商名 + 日期
- 毛净重/体积合同通常没有 → 与用户确认或按经验估算并注明

### A6 生成报关单（xls）

**xls 旧格式必须用 xlutils.copy 复制模板再改单元格**（保留海关格式），openpyxl 不支持 .xls：

```bash
# 先 dump 模板拿坐标 → 写 fill_spec.json（{"sheet":0,"cells":{"行_列":值}}）→ fill
"$PY" "$SKILL_DIR/scripts/xls_tpl.py" dump "<模板报关单.xls>" --json > coords.json
"$PY" "$SKILL_DIR/scripts/xls_tpl.py" fill "<模板.xls>" "<输出.xls>" fill_spec.json
```

关键单元格（中国海关标准格式，29行×12列，见 references/sample-formats.md 坐标）：

| 单元格 | 内容 |
|---|---|
| 收发货人/生产销售单位 | 供应商中文名 + 统一社会信用代码 |
| 贸易国(地区)/运抵国 | 目标国（如俄罗斯） |
| 境内货源地 | 发货城市 |
| 成交方式 | DAP（来自合同条款） |
| 合同协议号/规格书编号 | `合同号/规格书号` |
| 件数/包装种类/毛重/净重 | 与箱单一致 |
| 商品行 | 项号 \| 商品编号(HS) \| 商品名称、规格型号 \| 数量及单位 \| 最终目的国 \| 单价 \| 总价 \| 币制 \| 征免 |
| 申报要素 | 1:品牌 2:出口享惠 3:外观 ...（来源：合同+图纸） |

**HS 编码、统一社会信用代码、毛净重、体积等合同里没有的字段 → 标 `[待补充]` 并列出问题清单问用户，禁止编造。**

### A7 三单一致性校验（程序化，不靠肉眼）+ 校验报告

```bash
"$PY" "$SKILL_DIR/scripts/validate_3docs.py" \
  --contract ocr_out/fields.json \
  --invoice "<单号>发票.docx" --packing "<单号>箱单.docx" --customs "<单号>报关单.xls" \
  --report "<单号>三单校验报告.md"
```

- 校验项：合同号/规格书号三单一致、发票金额=合同总金额（优先 TOTAL 行，防单价误判）、箱单与报关单数字互通、合同关键编号全覆盖
- **校验报告是交付物的一部分**，随三单一起给用户（证据链）
- 空白归一化已内置：docx 公司名可能用不换行空格 `\xa0`，直接 `in` 匹配必失败，脚本先 `re.sub(r"[\xa0\u2007\u202f\s]+", " ", s)` 再比
- 退出码 0=通过 / 1=有不一致（报告照常输出，人工修正后重跑）

## 工作流 B：拍品清单 + 图纸 → 询价表

### B1 读拍品清单（xls）

xlrd 读取。典型列（乌克兰语，注意与俄语区分）：

| 列 | 原文 | 含义 |
|---|---|---|
| A | Lot | 序号 |
| B | Одержувач | 收货方（保留原文） |
| C | Найменування ТМЦ | 品名（俄语词根，如 Втулка ч.4-435281） |
| D | ОВ | 单位（шт = 件） |
| E | Кіл-ть | 数量 |
| F | Мінімальна ціна | 最低价（通常为 0/空，**不写入询价表**） |
| G | Додаткова інформація | 附加信息 |

语言判别：乌克兰语用 `і/ї/є` 字符与 `Найменування/Кіл-ть/Одержувач`；俄语用 `Наименование/Кол-во/Поставщик`。翻译按俄语词根走（查 scripts/glossary.json）。

### B2 解压图纸 ZIP + 建立映射

- 子目录名模式 `N-品名 ч.件号` ↔ 清单 Lot N 一一对应
- 每项内含 JPG/PDF/TIF 图纸（TIF 多为 300dpi 扫描件），处理方式见 B2.5
- 映射失败时列出无法映射的目录名与清单人工比对（可能子目录名缺 ч.件号）

### B2.5 图纸 OCR 处理（TIF→PNG→Tesseract，OCR.space 兜底）

**输入识别**：图纸文件常为 TIFF 扫描件（微信/邮件传输）、JPG/PNG 照片、PDF 扫描件。

**Step 1 — TIF → PNG 转换**（Pillow；Windows 系统 pip 可能被锁，一律 venv）：

```python
from PIL import Image
img = Image.open("drawing.tif")
if img.mode in ("CMYK", "RGBA", "P", "LA"):
    img = img.convert("RGB")
elif img.mode == "L":
    img = img.convert("RGB")
img.save("drawing.png", "PNG")
```

**超大片幅（decompression bomb）**：传真/扫描管线可能产出 1.8 亿像素级文件。Pillow 默认限制 ~178MP 会抛 `DecompressionBombError`，打开前先 `Image.MAX_IMAGE_PIXELS = None`；GIF 多帧取面积最大帧，存 PNG。

**Step 2 — OCR 引擎**（优先级：Tesseract > OCR.space > RapidOCR）：

**① Tesseract（首选，本地 OCR 引擎）**：

- `winget install --id Tesseract-OCR.Tesseract --silent --accept-source-agreements`；俄语包 `curl -L https://github.com/tesseract-ocr/tessdata_fast/raw/main/rus.traineddata -o rus.traineddata` 放入 tessdata 或用户可写目录
- **中文用户名铁律**：中文路径会让 `TESSDATA_PREFIX` 传给 tesseract.exe 时乱码（\"does not exist, ignore it\"）→ **永远用 `--tessdata-dir <临时目录>`**
- 运行：`tesseract drawing.png stdout -l rus+eng --tessdata-dir <临时目录>`

**② OCR.space（Tesseract 不可用时兜底）**：
- 图缩到 max 1600px、JPEG q85 压到 <1.5MB（免费限额），`urllib.parse.urlencode` 构造 POST；超时 120s；混排默认 `language=\"eng\"`，纯西里尔换 `\"rus\"`

**③ RapidOCR（离线最后备选）**：全离线 ONNX 推理，俄语数字可用但汉字易误读（`7`→`了`），仅在前两种都不可用时启用。

**OCR 参数**（工程图纸，Tesseract）：

| 参数 | 设置 | 理由 |
|---|---|---|
| 语言 | `-l rus+eng` | GOST/ДСТУ 图纸常俄英双语标注 |
| PSM | 默认 3；乱码时 `--psm 6` | 混合文本+尺寸标注布局 |
| 标题栏 | 裁剪右下区域放大 12-16x，psm 6/10 | 小字缩写密集 |

**Tesseract 常见数字误读（工程图纸）**：`70.`→`10.`、`5.*`→`3.*`、`То.`→`10.`（西里尔 Т 像 1）、`S16.`→`6.`。编号列表必须对照预期模式人工核验。
### B3 逐项翻译

- 保留俄语原名 + 中文翻译：`Втулка ч.4-435281 | 衬套 件号 4-435281`
- 查 scripts/glossary.json（141 词条），未收录的词按行业常识翻译并**回写 JSON**（唯一真源，改后重新生成 references/glossary.md）
- 翻译结合图纸内容确认（如 Вал полый выходной 看图纸确认空心轴）

### B4 提取单重/关键参数（图纸标题栏固定打法）

- 从图纸标题栏提取重量（俄语 `Масса` / `Вес`，英语 `Weight`）
- **固定打法**：扫描 TIF → 渲染 300dpi PNG → 裁右下角标题栏区域 → OCR 定位 `Масса/Вес` 行 → 提取数值
- **标题栏 Масса 格定位**：ГОСТ 2.104 小标题栏中 `Лит|Масса|Масштаб` 三小格在标题栏第一行最右侧；值行在其正下方；不同图纸标题栏 y 起点差异大，先扫描右下区域暗像素行分布定位，再裁剪放大 12-16x OCR（psm 6/10）
- **表格式系列图纸标题栏 Масса 空白（关键坑）**：一个图号覆盖多规格的系列图纸，标题栏 Масса 格**通常留空**——单重必须查图纸内**尺寸表**（表含 `Масса` 列，按规格行取值），表里没有的定制规格只能沿用客户清单值并标 `[待核]`
- **Масса 格空白验证**：OCR 反复读不出数字时，把该格二值化转 ASCII 像素图，无字形 = 空白（不要继续浪费时间 OCR）
- **同件号多张图纸交叉验证**：同一 ч.件号 出现多次取一致值，不一致标 `?` 人工定
- 无法确认的标 `?`

### B4.5 ⚠️ 材质标准必须以图纸标题栏为准（乌克兰招标实战教训）

- **乌克兰客户图纸材质标准是 ДСТУ（乌克兰国家标准），不是俄罗斯 ГОСТ**（如 60С2ХФА → ДСТУ 8429:2015 ≠ ГОСТ 14959-79）
- **禁止凭常识/经验编造材质**：曾把定径模写"模具钢"（编造），图纸实际是 60С2ХФА-Ш 弹簧钢。每个 Lot 的材质必须来自该图纸标题栏 OCR，无法确认就写"按图纸"并列入待核项
- **图号以图纸标题栏为准**：zip 文件夹名/清单名可能简化（如清单 Т3-20-К-08，图纸 Т3-20-К-08А）
- **结构对齐客户清单模板**：询价表 xls 采用客户清单的列结构，不要擅自换成公司自创结构
- **列数/表头=自己的逻辑，单元格内容=模板逻辑**：客户清单模板常有表头错位——**表头修正对齐即可，数据单元格必须逐格沿用模板原值**（中文翻译用客户清单原文，单重沿用模板值，单价空、总价 0、工期空）。图纸 OCR 得到的材质/图号/技术要求写入独立的核对报告（md），不进询价表内容列
- 单重来源要区分：图纸标题栏确认 vs 清单沿用，沿用值必须标注"待与客户确认"

> 完整招标批次样例（目录解剖 + 流水线 + 坑）：见 `references/worked-example-interpipe-tender-batch.md`。

### B5 生成询价表（xls）

**列结构 = 复制模板，禁止自创**（曾自创 8 列结构被用户要求按模板重做）。典型 9-10 列：

```text
col0 Lot | col1 Receiver | col2 Name(俄语原文) | col3 中文翻译 | col4 Quantity | col5 单重 | col6 单价 | col7 总价 | col8 工期
```

- **俄语品名与中文翻译是两个独立列**，不合并进一格
- 模板表头可能有错位（如第 4 列标 Units 但数据实为中文翻译）——照抄模板原样，勿"纠正"
- Receiver 列每行保留原文，不得删除
- 单重必须是独立数值列，嵌进规格文本会破坏工厂按列汇总
- 单价/总价留空待报价；用 xlwt 新建（或 xls_tpl.py 套模板样式），sheet 名保持原样

### B6 校验

- 询价表行数 = 清单 Lot 数
- 俄语品名原文逐项保留，中文翻译无遗漏
- 数量、单位与清单一致
- **合计数量 = Σ逐行数量（程序化求和）** — 肉眼不可靠（曾把 130 写成 76），必须脚本求和比对
- **列结构逐列与模板核对**（列数/表头/列序一致，禁止自创列名）
- 俄语品名/中文翻译分列核对，单重列存在且为数值（`?` 例外）

## 工作流 C：图纸翻译注释标注

用户要求"把翻译文本注释到图纸对应位置" / "所有中文注释标注在对应的原文旁边"时走本节。**两种方式按顺序尝试**：

### C1 首选：OCR → 注释对照表（用户自行加图）

当用户说注释"不准确"/"位置不对"，或明确"你负责提取，我来添加"时用此方式 —— **安全默认**（扫描图上自动像素级定位难做准）。

1. 对图纸 OCR（见 B2.5）提取全部俄文 + 英文标注
2. 人工清理 OCR 输出（修正乱码、重建编号列表 — Tesseract 常把 `10.` 读成 `70.`/`То.`）
3. 建注释对照表：标题栏信息（图号/品名/材质/标准）、技术要求 1-10 俄中对照、位置标注、表面粗糙度符号、剖面视图引用
4. 保存 `[文件名]_注释对照表.md` 到图纸所在目录，交付用户粘贴到图上

**对照表结构**：

```markdown
# 图纸注释对照表 — [图号] [产品名]
> 文件：[源图片文件名] | 生成方式：OCR 提取 + 翻译

## 一、图纸标题栏 / 总信息
| 原文（俄文） | 中文翻译 | 说明 |
| 2045-141 | 图号：2045-141 | 图纸编号 |
| Насос KRSH | KRSH 型泵 | 泵型号 |
| Сталь 12X18H12M3T | 钢材 12X18H12M3T | 材质牌号 |

## 二、技术要求（序号 1-10）
| № | 俄文原文 | 中文翻译 | English |
| ① | Точность отливки 12-11 ГОСТ 26645-85 | 铸造精度 12-11 级 | Casting accuracy... |

## 三、图纸标注文本（按位置）
| # | 俄文标注 | 中文翻译 | 建议位置 |
| ① | Язык спирали | 螺旋舌 | 指向蜗壳舌部 |
```

**用户说"标注在原文旁边"= 内联放置，禁止外围标注框+引线**（曾明确被拒）。中文翻译放在对应俄文行**紧邻右侧/下方**，跟随原布局。密集排不下时用「数字红圈标记 + 底部对照表」兜底。

### C2 自动内联标注（PIL）

仅当用户要求自动标注且 C1 未被拒。Pillow + Windows 中文字体（绝对路径 `C:/Windows/Fonts/msyh.ttc`，先 `os.path.exists()` 验证）。

- **文本行检测**：Tesseract 不可用/乱码时按暗像素密度逐行扫描定位（暗像素阈值 R<120；行间距 >3px 分行；步长 2px；大图纯 Python 约 30-60s）
- **布局规律**（300dpi 右半幅）：顶部图号；中部技术要求编号列表（可能 2-3 列）；下方规格表；底部标题栏
- **内联放置**：俄文行尾 +8px 写中文（蓝 `(0,70,200)`）；超出右缘 → 数字红圈标记 + 底部对照表（红表头白字，隔行浅蓝底）
- **辅助标注**：材质等号（右上角蓝，`Сталь 12X18H12M3T ≈ AISI 316Ti / EN 1.4571`）、关键尺寸（左侧绿）、品名（深蓝）
- **保存**：直接画在 RGB 图上存 PNG；用 `Image.alpha_composite` 而非 `blend`（blend 洗色）

**C1/C2 选择信号**："我来添加注释到图片"→ 立即切 C1；用户抱怨过定位不准 → C1；图纸文字密集多列 → C1；含手写标注 → C1。

> 泵体蜗壳完整案例（标题栏/技术要求/位置标注逐项）：见 `references/worked-example-krsh-pump-housing.md`。

## 翻译规范

1. **件号格式统一**：`件号` + 空格 + 原编号原样保留（含引号/斜杠/点），如 `密封皮碗 件号 НТ.ГП.SMS/13" 3/8.15225342 装配件`
2. **英寸标记**：`13" 3/8` = 13又3/8英寸，中文统一写 `13又3/8英寸`；纯数字后缀 `244,5` 直接译 `244.5`
3. **俄语逗号=小数点**：339,72 → 339.72；Ф1/4 = 1/4 英寸
4. **СБ / ч. / шт 缩写**：СБ=装配件（品名尾部）、ч.=件号、шт=件
5. **乌克兰语按俄语词根翻译**：Найменування→наименование→名称，Кіл-ть→количество→数量

## 异常路径

| 异常 | 处理 |
|---|---|
| rus.traineddata 缺失 | 仅用 eng（俄语变拉丁转写），verify_list 提示"需人工校"；补装：下载到 tessdata 目录 |
| ukr.traineddata 缺失 | 自动降级 rus+eng（乌克兰语清单多为文字型 XLS 不受影响，仅扫描图纸标题栏受影响） |
| vision 工具不可用 | 走 verify_list 人工核对路径（A1.5 路径 2），只核对清单条目 |
| 多页混合 PDF（首页扫描+次页文字） | ocr_pdf.py 逐页判断分别处理，页码标记进全文 |
| ZIP 子目录与 Lot 映射失败 | 列出无法映射的目录名，与清单人工比对（可能子目录名缺 ч.件号） |
| 模板文件找不到 | 问用户要模板目录；模板缺失时明确告知无法保证"格式完全对应" |
| 合同未载明字段 | 沿用模板同订单数据并注明来源，或标 `[待补充]` 问用户，禁止编造 |
| OCR 长数字错位 | verify_list 强制列出需核对；合同号位数不固定（16-20 位），以人工核对为准 |
| 图纸 ZIP 解压后子目录含 PDF（.jpg.pdf 命名） | 按扩展名判定：`.pdf` 后缀先 pymupdf 渲染，`.jpg.pdf` 双扩展名先剥 .pdf 再按图处理 |
| OCR.space 400 错误 | base64 拼接出错，用 `urllib.parse.urlencode` 构造 POST |
| OCR.space 413 错误 | 图超 1.5MB 免费限额，缩到 max 1600px 再压 JPEG q85 |
| 微信传输 TIFF 命名混乱 | 常见 `img_t{timestamp}_n1 (1)_01.tif`，按内容识别不按文件名 |

## Pitfalls

- **短数字替换必须限定范围（实测踩坑）**：全局字符串替换 "80"→x 会误伤合同号（含 "80"）→ 箱单合同号被改坏。铁律：**段落只做完整词替换**（日期/规格书号等长词），**数值列只做表格单元格整值匹配**（`cell.text.strip() == 目标值` 才替换）
- **模板表格行结构以 XML 为准，勿信 python-docx 视图**：存在 gridSpan 跨列合并时 row.cells 视图错位。改表格必须 XML 层：`tbl.findall(w:tr)` → `tr.findall(w:tc)`；w:t 嵌套在 w:p/w:r 下，读写用 `tc.iter(w:t)` 而非 `findall`（findall 只找直接子元素会漏）
- **多商品行订单清空多余行**：模板商品行 >1 时，新订单只保留一行商品，其余行清空（保留格式），Total 行独立填写合计——勿把 Total 行当第二商品行
- **xlutils.copy 的 write 默认样式覆盖原格式**：不传 style 写入会把单元格变成 Arial/左对齐/无边框/无换行。必须用 `xls_tpl.xf_to_style(rb, xf_index)` 从 xlrd XF 构造 xlwt XFStyle（保留字体/对齐/边框/数字格式/换行）
- **xls 列位以 dump 为准**：首次用模板前必须 `xls_tpl.py dump` 核对列位再写
- **单格混排必须重算对齐空格（实测踩坑）**：单格内「品名+数量+单价+金额」混排、空格推到固定列位时，只替换数字不重算空格 → 数字与表头错位（规则见 A4）
- **扫描合同 0 字符**：pymupdf `get_text()` 为空 = 扫描件，必须渲染 + OCR，别硬读；OCR 后人工校对全部数字
- **OCR 数字噪声**：长数字极易错位；俄语逗号是小数点（339,72 = 339.72）
- **合同号位数不固定**：样例 18 位（旧版误标 19 位导致 `\d{19}` 匹配失败），校验按 16-20 位宽松处理
- **乌克兰语 ≠ 俄语**：用 i/ї/є 字符与 Найменування/Кіл-ть 判断；品名翻译按俄语词根处理
- **.xls 旧格式**：xlrd 只能读；写/改必须 xlwt / xlutils.copy（openpyxl 不支持 .xls）；一律用 scripts/xls_tpl.py
- **模板里的公司名**：模板可能是其他公司的，生成时必须替换为合同中实际供应商/买家，仅保留格式
- **中文路径 + tesseract**：必须 `--tessdata-dir`；TESSDATA_PREFIX 在中文用户名下乱码（脚本已内置）
- **pymupdf 不认 MSYS 路径**：Windows 原生库只接受 `C:/...` 或 `C:\...`，脚本传参用 Windows 路径（实测踩坑）
