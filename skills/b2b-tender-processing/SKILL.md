# B2B 招标信息整理与询价单生成（通用模板）

> 本版为跨设备通用版：路径、账号、客户名、项目编号均已参数化/匿名化。以钢厂 SRM（NLMK 类）招标为实例，其他 SRM 平台可参照。

## 环境要求与配置

- Python 依赖：`pymupdf`（读主 PDF）、`openpyxl`（生成询价单）；扫描件 OCR 备用 `rapidocr-onnxruntime`（纯 ONNX、支持西里尔文）或 PaddleOCR PP-OCRv5。
- 交付根目录：默认用户桌面；agent 运行账户 ≠ 桌面用户时必须显式指定（如环境变量 `TENDER_OUT_DIR`），不要用 `~` 解析。
- 上游：招标邮件的抓取与按天归档走 `b2b-mail-capture` skill；本 skill 从归档目录（`邮件抓取结果/<YYYY-MM-DD>/..._附件/`）取源。

## 触发条件

- 用户给出邮件结果目录路径，要求整理其中新收到的招标
- 用户指定招标编号列表（如 `20155619, 20155628`），要求逐个整理

## 铁律

1. **模板优先**：所有输出格式参照既有的标准询价文件夹实例，**不自行设计格式**。⚠️ 模板文件夹可能被清理而找不到；找不到时**直接按本 skill 的 11 列规范（Step 4）生成即可**——本规范即最终版（已与模板逐列核对过），不要因模板缺失而卡住，也不要改用其它格式（如简易 4 列 Name/ID/Quantity）。
2. **不要放入 .eml 文件**：项目文件夹中只保留 PDF + 附件，.eml 留在邮件结果源目录。
3. **输出到交付根目录（桌面）**：整理结果放在 `<桌面>/{日期}-{标段}{中文品名}-{状态}/`（现行规范，见 Step 2）。不要放进「报价单」等子目录。
4. **询价单格式**：纯表格——第 1 行是表头，第 2 行开始是数据。不要在第 1-4 行写招标编号/采购方等元信息。
5. **非 SRM 邮件询价同样适用本规范**：没有 0.PDF/招标编号的纯邮件询价也走同一套标准——桌面 `{YYMMDD}-{品名}-{状态}/`（无标段号则省略）、附件平铺编号 `1..n`、不放入 .eml、必须生成 `{品名}等询价单.xlsx`。**禁止按类别分子文件夹（01-邮件/02-图纸/…）**——那不算标准询价单文件夹。
6. **抓取前必查重**：任何抓取动作（手动补抓指定邮件 / 下载附件）**执行之前**，必须先查本地是否已有相同内容，已存在的直接复用，禁止重复下载。查重三步：① 按 UID grep 邮件结果目录；② 按主题关键词/发件人 grep；③ 附件用 md5 判定唯一性。曾出险：手动抓某客户邮件未先查本地，把已落盘的邮件重抓进新目录，同一封邮件存 3 处。

## 工作流程

### Step 1 — 读取 0.PDF（主招标文件）

每个招标文件夹中，`0.PDF` 是 SRM 系统导出的主招标 PDF。用 PyMuPDF (fitz) 读取：

```python
import fitz
doc = fitz.open("0.PDF")
for page in doc:
    text = page.get_text()
```

从中提取：
- 招标编号（Номер конкурса / № процедуры）
- 采购方（Заказчик / Организатор）
- 项目名称（Наименование / Описание）
- 截止日期（Дата окончания приема предложений / Период подачи）
- 行项明细（Поз. / № продукта / Название / Количество / Ед. изм.）

> 字段级解析笔记（行项表文本顺序错乱的判定规则、采购方备注必摘条款、附件核对法）：`references/nlmk-srm-main-pdf-notes.md`（随 b2b-mail-capture 分发，两个 skill 共用）。

### Step 2 — 创建项目文件夹

```
<桌面>/{日期}-{标段}{中文品名}-{状态}/
```

命名规则（现行规范）：
- 文件夹名 = `{日期}-{标段}{中文品名}-{状态}`，例如 `260818-20155514分配头-待报价`
- 日期 = YYMMDD（**生成当天**，不是邮件到达日）；标段 = 完整 8 位招标编号；中文品名 = 核心产品中文名；状态 = `待报价`（报价前）/ `已报价`
- 示例：`20155619_Главный вал 1068868619` → `260813-20155619主轴-待报价`

### Step 3 — 整理附件

将招标文件夹中的附件移入项目文件夹，按顺序编号：

- 从 1 开始递增编号：`1 {原文件名}`、`2 {原文件名}`...
- 附件包括：PDF 图纸、Excel 清单、Word 文档等
- **0.PDF 保持原名不变**（作为主招标文件）
- **不移动 .eml 文件**（留在源目录）

```python
attachments = sorted([f for f in os.listdir(src) if not f.endswith('.eml') and f != '0.PDF'])
for i, f in enumerate(attachments, 1):
    shutil.copy2(os.path.join(src, f), os.path.join(dst, f"{i} {f}"))
```

### Step 4 — 生成询价单 Excel

**格式规则（关键——多次纠正后的最终规范，已与模板逐列核对）：**

- **第 1 行即表头，第 2 行起数据**，不要在第 1-4 行写招标编号/采购方/币种/条件等元信息
- **表头 11 列**（`\n` 在单元格内换行）：
  `序号` | `物料号` | `名称` | `中文名称` | `数量\npcs` | `图纸单重\nkg` | `总重` | `材质` | `单价` | `总价` | `交货期\nLead time`
- **数据列映射**：序号=1..n；物料号=PDF 的 `№ продукта`（装配体拆件时=部件图号）；名称=俄文原名；中文名称=中文翻译；数量=整数（俄文逗号=小数点，见陷阱）；图纸单重/材质 **从图纸 BOM/标题栏提取**（扫描件 OCR 不了写 `按图纸`，禁止编造），总重=`=E*F` 公式；**单价/总价/交货期 留空**（公司内部上报数据，铁律）
- **汇总行**：最后一行为 `total`，A:C 三列合并，E/G/J 列放 `=SUM(...)` 公式
- **格式细节**：表头字体 Arial 11，数据行 Times New Roman 11，全表 thin 边框 + 居中 + 自动换行；列宽 A=9 B=14.25 C=34.5 D=27.6 E=9 F=11.75 G=11.75 H=17.5 I=11.63 J=11.63 K=11.75；表头行高 30，数据行高 32

**实现**（openpyxl，完整可复用脚本见 `references/询价单生成.py`）：

```python
header = ["序号", "物料号", "名称", "中文名称", "数量\npcs", "图纸单重\nkg",
          "总重", "材质", "单价", "总价", "交货期\nLead time"]
# ... 详见 references/询价单生成.py（含字体/边框/列宽/汇总行全套）
```

### Step 5 — 复制 0.PDF

将 0.PDF 复制到项目文件夹根目录（保持原名，不编号）。

### Step 6 — 验证

- 确认项目文件夹中：`0.PDF` + 编号附件 + 询价单 .xlsx，无 .eml
- 询价单明细与 PDF 原文核对：№、产品名、数量、单位逐项一致
- 附件数量与 PDF 中提到的附件数一致

## 陷阱

- **参考文档可能过时**：旧文档描述「第 1 行写招标编号、第 2 行写采购方、第 5 行开始表头」是错误的。实际模板是纯表格，第 1 行就是表头。**以实际模板文件/本规范为准，不要相信旧文档描述。**
- **不要放入 .eml**：eml 保留在邮件结果源目录即可。
- **不要放到报价单子目录**：输出是交付根目录（桌面）。
- **附件排序**：附件必须用数字编号前缀，按字母顺序排列。
- **询价单文件名**：`{标段}{中文品名}等询价单.xlsx`（如 `20155514分配头等询价单.xlsx`，与文件夹中文品名对齐，无空格、含「等」）；**文件夹名才带日期前缀** `{日期}-{标段}{中文品名}-{状态}`。
- **俄文逗号=小数点**：0.PDF 里 `Количество` 是俄式数字，逗号是小数点、句点是千分位。`12,000 ШТ`=12 件，`4.800,000 ШТ`=4800 件，`2,000 ШТ`=2 件。询价单「数量」列填换算后的**整数**。
- **PDF 提取数字/字母混淆（3↔З）**：SRM 主 PDF 文本层提取时常把数字「3」误识成西里尔字母「З」，并丢失图号中的句点。如 `Л6ЗС`→`Л63С`、`ПР6ЗС`→`ПР63С`、`00011`→`00.011`、`000 00СБ`→`00.00СБ`。还原时依据左右对称件规律（ПР=правая 右、Л=левая 左、同一 63С 系列）判断，并在交付报告里提示对照附件图纸标题栏复核，禁止照抄乱码。
- **主 PDF 行项名称被列宽截断**：`Название` 列过窄时图号被截断，完整图号以附件图纸标题栏为准；可依据左右对称件补全，但**不要臆造缺位数字**，拿不准就保留可见部分并在报告标注。
- **Windows 文件名非法字符**：项目名里俄文缩写常含 `/`（如 `р/в`、`д/изм`），写文件名/文件夹名前必须替换（`/`→`-` 或删除），否则 `FileNotFoundError`。文件夹名用下划线 `_` 天然避开。
- **.7z 图纸附件**：邮件附件可能是 .7z 图纸包（每个对应一个物料号）。解压到 `Чертежи {物料号}/` 子文件夹，并**拉平嵌套目录**（部分 .7z 内还有一层同名子目录）。Windows 用 7-Zip CLI：`"C:/Program Files/7-Zip/7z.exe" x 包 -o目标 -y`。
- **同一招标跨多日重复出现**：同一招标编号可能在多个日期目录都有。以**最新日期**目录的邮件为准（附件最全），不要重复建文件夹。
- **主招标文件版本号不固定（0.PDF/1.PDF/2.PDF/4.PDF）**：SRM 导出的主招标 PDF 命名随版本变化——`20155582/1` 的源文件是 `1.PDF`（版本 1），`20155445/2` 是 `2.PDF`。**不是所有招标都有 `0.PDF`**。整理时识别附件列表里第一个 `.PDF` 编号文件作为主招标文件，统一复制为 `0.PDF` 放入项目文件夹（版本号可在交付报告注明），不要因为源文件叫 `1.PDF` 就误当普通附件编号。
- **缺主招标 PDF（只有图纸包）**：部分招标邮件只发 .7z/.zip 图纸包、没有 0.PDF/1.PDF 主文件。此时行项数量/物料号/币种无从提取，只能从 .7z 文件名（含 ОЗМ 编号）推断产品行项，生成**骨架询价单**——数量标「待确认」、单重/材质标「按图纸」，交付报告明确标注缺主 PDF 及待补字段，禁止编造数量。
- **附件完全缺失（索引有记录但文件没落地）**：邮件索引里有该标号记录（主题+附件列表），但 eml 和附件文件都不在磁盘。这是抓取工具漏抓，先全盘按 UID `find` 确认，再告知用户重抓该邮件——**禁止凭索引里的附件列表编造行项**。
- **邮件完全漏抓（索引里连记录都没有，抓取盲区）**：用户报某标号邮件「明明有这封邮件标题」，但本地 grep 零命中、索引里也没有该 UID。这是抓取工具在两次运行之间漏掉了中间到达的一批邮件——它们既没落盘成 .eml、也没写进断点（done_uids 出现 UID 断层）。定位法：① grep 邮件结果目录（无结果=没抓）；② 连 IMAP 用 `uid("search", None, "SUBJECT", "<标号>")` 拿真实 UID/日期；③ 对照断点的 done_uids 找断层。补救：直接重跑抓取工具（默认增量）即可补齐漏抓邮件并更新断点，**不需要全量重拉**。
- **邮件已自动抓到但用户以为「没抓取」（假阴性，勿重抓）**：定时邮箱监控抓到邮件后只写日志 + 落盘，**不会推送/通知用户**——邮件可能已落盘数天而用户毫不知情，这是常态不是故障。排查按序：① 查定时任务日志；② 查监控断点的 last_uid；③ 按 UID find 落盘目录；④ 对照抓取工具的 done_uids。日志显示已抓 + 磁盘有文件 → 直接报告「已自动抓取 + 时间 + 位置」，不重抓。完整排查流程见 `references/email-auto-fetch-diagnostics.md`。
- **系统通知邮件被黑名单拦截（勿当漏抓）**：抓取工具内置黑名单——系统通知、异地登录/账户安全/验证码、noreply/postmaster/bounce、退信、spam 等命中即**不落盘**且记入断点。用户问「为什么没抓到 XX 通知邮件」时，先按发件人/主题判断是否命中黑名单——命中是**故意跳过**，不是漏抓，不要建议全量重拉（重拉也会再次跳过）。注意黑名单通常只挡下载层：监控脚本的触发层（放宽成「任何新邮件都触发」）仍会对系统通知触发一轮拉取流程（建目录+写日志，下载层才跳过）。两层状态要分开说明。
- **询价/ 文件夹按「日期_主题」分装**：抓取工具的询价归档按**归一化主题**（循环去除 Re:/Fw:/回复：/答复：/转发： 前缀 + 引号/括号/横线噪音，前缀后必须紧跟分隔符或空白，否则会误剥英文单词如 request→quest）归组，每组一个子文件夹 `询价/<YYYYMMDD>_<主题>/`（eml/ + attachments/ + 组内索引），日期取组内最新邮件日期；同组重复附件 **md5 去重**。用户通过文件夹名即可判断内容是否值得查看。同一询价跨天转发会合并进一个文件夹。
- **标号缩写映射（后四位）**：用户常用后四位缩写标号（5582→20155582）。映射时先找 `招标_201xxxxx` 文件夹；找不到时列出索引里所有**尚未处理**的招标编号让用户确认（可能是笔误或邮件尚未收到），不要擅自猜一个编号顶上去。
- **0.PDF 必须保留**：作为项目文件夹中的主招标文件，不编号，保持原名 `0.PDF`。
- **非 SRM 邮件询价（无 0.PDF/招标编号）**：标准询价单文件夹同样适用——桌面 `{YYMMDD}-{品名}-{状态}/`（无标段号省略标段）、附件平铺编号 `1..n`、不放入 .eml、生成 `{品名}等询价单.xlsx`（11 列模板）。**不要按类别分子文件夹**。源附件取**最新日期**目录；询价源附件的位置：`邮件结果/<YYYYMMDD>_<邮箱>/询价/<邮件日期>_<邮件主题>/attachments/`（每封询价一个小文件夹，按『日期_主题』命名，同日同主题合并；顶层 `询价/询价索引.txt` 总索引含发件人列）。
- **附件跨多个日期目录重复**：同一封询价的附件散落在多个日期目录。用 md5 判定唯一性，同一 md5 只留一份。
- **扫描件 PDF（无文本层）提取产品参数**：`page.get_text()` 返回 0 字符时，渲染 300dpi PNG 后 OCR。PaddleOCR 不可用时的快速替代：`rapidocr-onnxruntime`（纯 ONNX、支持西里尔文），`RapidOCR()(png)` 返回 `[(box, text, conf)]`。OCR 易把西里尔字母认错（Р→P、е→e、Ы→b），但数字/拉丁字段（ID、重量）可信度高。
- **询价邮件未给数量**：客户询价只要求技术商务方案、不列采购数量时，询价单数量列留空不编造，总重/总价公式不填，交付报告标注「数量待确认」。
- **疑似重复附件**：不同文件名但 OCR 内容一致（同 ID/型号/重量）时，保留全部行项与附件一一对应，交付报告提示向客户核对是否重复文件。
- **客户直接转发的询价文件夹（非邮箱抓取产物，勿走查重/抓取流程）**：客户会把询价以文件夹形式直接给过来（常带同名 `.zip`）。处理要点：① 先核对 .zip 与解压文件夹文件数/大小/md5 一致性，防止漏附件（zip 内文件名可能乱码但大小一致可判同）；② 此类来源在邮件结果目录**无 UID/索引记录**，是正常现象，不要按铁律 6 查重也不要建议重抓；③ 附件直接按字母序编号 `1..n` 进标准文件夹，生成 11 列询价单。
- **扫描件技术任务书（ТЗ）OCR 信任分层：表格可信、尺寸草图数字不可信**：PP-OCRv5（ru，CPU）对 ТЗ 的识别质量分两档——**表格类内容高置信**（材质、工作参数、温度范围、湿度，置信度 0.9+），**Рисунок/Эскиз 上的尺寸数字基本不可用**（孤零零数字置信度 0.3-0.5，无法还原）。落单规则：材质列可照表填（多档材质都写、注明「按技术要求表 X」）；单重标「按图纸」；**尺寸类必须人工核对原图**并在交付报告标注「图 1 尺寸待人工核对」，禁止拿低置信度数字进询价单。附带：技术任务书里「需要改进型/高于原厂防护等级」是报价关键输入，须在交付报告显著传达给厂家，不能只当 1:1 复刻询价。
- **附件带 Описание позиций xlsx 时以其为行项权威来源**：部分招标在主 PDF 外另附 `Описание позиций (003).xlsx` 官方清单，含完整名称、材质（Материал изготовления）、技术参数、原厂目录号、SP number——主 PDF 的「Название」列常被列宽截断。处理：名称列用 xlsx 全称、材质列用 xlsx 材质（译中文），数量仍以主 PDF 为准并逐项核对两源一致；技术参数/目录号不写入询价单，但保留在交付报告作为厂家报价关键输入（电子件尤甚）。
- **image001.png 等内联图片不是附件**：邮件附件目录里 `image001.png`（小尺寸 RGBA）是邮件正文内嵌装饰图/logo，与 .eml 一样不要编号进询价文件夹；用 PIL 打开看尺寸/模式即可确认，交付报告一句话说明已排除。
- **装配件按明细表展开（用户指定「按明细表汇总」）**：询价单行 = 图纸明细表（спецификация）每一行；**「数量」列 = 单台数量 × 标段台数**（10 台 → 单台 1 → 填 10；单台 3 → 填 30；单台 0,8 м → 填「8 м」文本，不写数字以免被当件数）；「中文名称」列末尾注明`（单台 N ×X 台）`保留可追溯性；「物料号」列写图纸零件代号（如 `5к.576.1`、`ГОСТ 7798-70`、`б/ч`），标段 SRM 行项号写在交付报告，不写进表。明细表「Масса」列可作单重（注意扫描件放大 2× 复核数字，如 `0,12` 与 `1,2` 极易混读）；ГОСТ 标准件行无质量 → 单重写「按图纸」。
- **扫描件图纸小字不可读时不做臆造**：先 `page.get_images()` 查内嵌源图尺寸——SRM 招标附件常是 150–200 dpi（A3 约 1650×2336 px），图框/明细表小字放大也无解。此类图纸的逐件单重写「按图纸」并在交付报告注明「图纸包随附，请厂家按图核重」，**禁止靠放大插值猜数字**。
- **装配图（СБ）标题栏 Масса 可能为空**：装配图的 Масса 栏空白、спецификация（сп/ПС）也无质量列（ГОСТ 2.106 规格表本就没有 Масса 列）→ 单重写「按图纸」，不要在报告里声称有重量；也不要逐件相加当总重。
- **多页图纸合计单重**：装配件图纸分多页多图号（如橡胶件 38,3 kg + 钢架 14,65 kg），整件单重 = 各页之和。填合计值，材质列写全组分，交付报告标注重量构成并提示向采购方确认是否含钢架等组件，禁止只填其中一页重量。
